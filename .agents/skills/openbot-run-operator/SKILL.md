# OpenBot.run Operator

Use OpenBot as the persistent conversational/team surface, not as the sole Factory Core transaction store.

1. Confirm the user means OpenBot.run, then inspect installed version, active server/client and observable UI.
2. Before commercial/client use, verify the current license and provider data terms.
3. Inventory providers, models, permissions, plugins, skills, routines, channels and workflows from observed state; do not infer account access.
4. Apply least privilege and test each change with a harmless bounded task.
5. Import the Chief Operator first, then one lead at a time. Keep consequential routines inactive until approved.
6. Record configured, validated, import-ready, blocked and unverified capabilities separately.
7. Never submit to Marketplace, share publicly, send externally, activate consequential automation, expose credentials or delete data without exact authorization.

For project-specific roles and order, read [team setup](references/team-setup.md). For current product concepts, consult official OpenBot.run docs/changelog and the installed UI.
