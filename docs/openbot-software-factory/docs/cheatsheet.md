# One-Page Cheatsheet

**Three layers:** OpenBot plans/specs/brand/client comms/QA → T3 Code or Codex codes/tests/opens PR → ChatGPT Dots draft/check on mobile. Files are the bridge; chat history is not.

**Handoff filenames:** `spec.md` → `ticket-01.md` → `handoff.md` → T3 worktree/PR → `result.md` → QA `review.md`. **No spec, no T3 thread. No acceptance criteria, no handoff. No review file, no merge.**

**Daily loop:** Morning 15 min: deadlines, blockers, handoffs, top 3, client IDs. Evening 10 min: results, review files, client updates, next actions, stop idle work.

**Tier routing:** T0 routine drafting/formatting; T1 synthesis/planning; T2 architecture ambiguity, high-stakes copy and final QA. Escalate with written uncertainty and reason. Keep context pack to spec + repo path + acceptance criteria + do-not-touch list.

**Agent creation order:** Intake Lead → Client Partner → Product Architect → Delivery Planner → QA Reviewer → Brand Lead → Content Strategist → Content Producer. Eight agents; disable unused roles.

**Five gates to add an agent:** weekly; distinct artifact; non-overlapping; tier-fit; clean handoff. Fail any gate → skill/prompt/template/manual.
